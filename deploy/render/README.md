# Deploy Neha on Render (Free plan)

Two services from `render.yaml` at the repo root (the original Blueprint; restored 2026-11-26):

| Service | What | Runtime | URL |
|---|---|---|---|
| `acr-neha-bot` | Neha: voice server, widget, avatar | Python (`pip install edge-tts numpy pillow`) | `https://acr-neha-bot.onrender.com` |
| `acr-neha-kb` | Knowledge base (search, saved answers) | Node, `kb/` | `https://acr-neha-kb.onrender.com` |

Free plan: each service sleeps after 15 min idle (first visit ~30-60 s), 512 MB RAM, no persistent disk.
The kb runs Gemini + keyword search (the local model needs ~1 GB; it was OOM-killed at 535 MB).

## Steps

1. **Render dashboard -> New -> Blueprint -> connect GitHub -> pick `Acr_bot`.** Render reads `render.yaml`.
2. **Fill the secret values it asks for** (never commit them):
   - `acr-neha-bot`: `GROQ_API_KEY`, `GEMINI_API_KEY` (required); `DEEPGRAM_API_KEY`, `BITRIX24_WEBHOOK_URL`,
     `OPENAI_API_KEY`, `SIMLI_API_KEY` (optional, leave empty if unused).
   - `acr-neha-kb`: `GEMINI_API_KEY` (required: the kb's search embeds each question with Gemini).
   - `KB_ADMIN_KEY`: type the **same** long random value into both services (the bot uses it to read the kb's
     saved answers). `HUMAN_BOT_ADMIN_KEY` is generated by Render.
   - Optional hardening: add `KB_SEARCH_REQUIRES_KEY=1` to `acr-neha-kb` so its public search answers only with
     that key (the bot already sends it).
3. **Upload the customer-call answers as a Secret File** (they are not in git, on purpose):
   `acr-neha-kb` -> Environment -> Secret Files -> Add -> filename `qa_pages.jsonl.gz.b64` -> paste the
   contents of the local file `qa_pages.jsonl.gz.b64` (796 KB; Render's limit is 1 MB per service).
   Then Manual Deploy -> Clear build cache & deploy, so the kb imports it at boot.
4. **Check** (replace the URLs if Render named the services differently):
   - `https://acr-neha-kb.onrender.com/health` -> `"ok":true`
   - `https://acr-neha-bot.onrender.com/health` -> `"ok": true`
   - kb log shows `[seed] qa bundle: 625 imported`; bot log shows `[fast] 625 answers indexed`
   - open `https://acr-neha-bot.onrender.com/` : autocarrepair.in with Neha (demo copy; trackers blocked,
     the site form answered locally, nothing reaches the live site).
5. **On the live website** (when approved), the developer adds before `</body>`:
   `<script src="https://acr-neha-bot.onrender.com/widget.js" data-persona="auto-car-repair" data-position="left" defer></script>`
   and `HUMAN_BOT_SITE_MIRROR` is set to `0`.

## Regenerating the secret file after knowledge-base changes

On the machine with the curated kb (`kb/data/kb.sqlite`):

```bash
cd kb && node src/qa_bundle.js export > /tmp/qa_full.b64
# then strip the local vectors to stay under 1 MB (see the 2026-11-26 commit message), upload again, redeploy
```

## Known limits on Free

- Sleep after 15 min: the first visitor waits for both services to wake up.
- Groq / Gemini free tiers rate-limit under load; Neha falls back to saved answers. A paid key fixes it.
- Recording is off (`HUMAN_BOT_RECORD=0`) until the privacy-policy line about recording is live.
- Leads are in `dry` mode until the website developer confirms the lead API.
